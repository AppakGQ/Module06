# Модуль 06 - Защита доступа к API (CSE5032 Разработка веб-сервисов)

Три работы, каждая - отдельный ASP.NET Core Web API (.NET 8):

| Папка | Работа | Порт | Что внутри |
|---|---|---|---|
| `01_Practical_ProductApi` | Практическая работа | 5161 | API Key (`X-Api-Key`), JWT, `[Authorize]`, Swagger |
| `02_Lab_TaskManagementApi` | Лабораторная работа | 5062 | Task Management API, JWT, Claims `name`/`role`, 6 тестов безопасности |
| `03_Homework_ProductsApi` | Домашнее задание | 5063 | Products API, JWT, Claim с именем пользователя |

В каждой папке: исходный код, `screenshots/` (скриншоты + `requests_log.txt` с сырыми запросами/ответами), `requests.http` и `README.md`.

## Запуск
```
cd 02_Lab_TaskManagementApi
dotnet run
```
(или открыть `Module06.sln` в Visual Studio и запустить нужный проект). Нужен .NET 8 SDK; пакеты подтянутся из NuGet при первом `dotnet restore`.
Если установлен только .NET 9/10 - поменяйте `<TargetFramework>` в `.csproj` на `net9.0`/`net10.0`.

Учебный пользователь везде: `student` / `12345`.
Секретный ключ JWT лежит только на сервере (`appsettings.json`); клиент получает токен и дальше шлёт только `Authorization: Bearer <token>`.

## Результаты проверок (реальные HTTP-запросы к запущенным приложениям)
Все сценарии из заданий пройдены: без токена -> 401, с корректным JWT -> успех, изменённый JWT -> 401, истёкший JWT -> 401.
Итоговые таблицы - файлы `screenshots/99_summary.png` в каждой папке.

Как получены "плохие" токены:
- изменённый: payload подменён (`name=admin`), подпись оставлена старой -> проверка подписи не проходит;
- истёкший: токен с корректной подписью, но `exp` на час раньше текущего времени (`ClockSkew = 0`, поэтому допуска нет).
